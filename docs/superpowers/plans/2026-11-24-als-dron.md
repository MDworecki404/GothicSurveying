# Skaning lotniczy z drona (ALS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Robota "Skaning lotniczy z drona": plan nalotu, autopilot, skaner liniowy z georeferencja GNSS/IMU z szumem, wynik LAS 1.2 / PTS + trajektoria CSV + opis.

**Architecture:** Czyste obliczenia w `calc/` (plan, georeferencja, zapis LAS), robota `job/AerialJob.hpp` na nowych wywolaniach `IWorld` z domyslnymi cialami (jak `ScanRay`), silnik tylko adapter. Plan lotu i trajektoria nie znaja sensora (struktura `SensorSpec`), zeby pozniej obsluzyc kamere.

**Tech Stack:** C++20 (testy g++ `-Wall`, `assert`), MSVC x86 dla wtyczki, Python (modele `.3DS`), PowerShell.

**Spec:** `docs/superpowers/specs/2026-11-24-als-dron-design.md`

## Global Constraints

- Obliczenia w `calc/` z testami `tests/test_*.cpp`; `powershell -File tests/run.ps1` musi konczyc sie `ALL OK`. Build: `powershell -File scripts/build.ps1` -> `BUILD OK`.
- Teksty w grze ASCII (bez polskich znakow), komunikaty po polsku; README/INSTALACJA moga miec polskie znaki.
- Commity lokalne, male, po zielonych testach i buildzie; **bez** `Co-Authored-By` i jakichkolwiek dopiskow atrybucji; bez push, wydan i merge.
- Makra windows.h: uzywaj `(std::min)(...)`; nie nazywaj zmiennych `near`, `min`, `max`, `rad2`. Funkcje z `__try/__except` bez obiektow z destruktorami.
- Plugin 32-bitowy: chmura zapisywana strumieniowo; wspolrzedne siatki (N ok. 5,5 mln m) w LAS z offsetem = floor(min), skala 0,001.
- Wartosci spec: obszar do ok. 300x300 m; AGL 30-150 m; predkosc 3-8 m/s; bateria 25 min, zapas 25%; zasieg promienia do 250 m; budzet `Tick()` 12 ms; LAS 1.2 format 3 (rekord 34 B), point source id = numer szeregu, czas GPS = czas symulacji.
- Silnik (`engine/`) tylko cienko; niepewne wywolania silnika: diagnostyka do `GothicSurveying.log` i prosba do uzytkownika o fragment, bez zgadywania.

## Review Focus

1. Wielokat z < 3 wierzcholkami lub zerowym polem: plan odmawia z komunikatem, bez dzielenia przez zero (Task 1).
2. Wielokat wklesly (L): kazda linia cieta na odcinki wewnatrz, bez szeregow lecacych poza obszarem (Task 1).
3. Bateria za mala na plan: `batteryOk=false` i start odmowiony z komunikatem (Task 1, 5).
4. Promien bez trafienia lub brak wysokosci terenu: bez punktu/bez awarii, czas symulacji plynie, plan wraca do wysokosci domu (Task 5).
5. Duze N/E (5,5 mln m) i przerwanie lotu w polowie: LAS z offsetem bez utraty mm, przerwany lot zapisuje czesciowy wynik (Task 3, 5).
